>
> 최종 업데이트: 2026-05-01

---

## 테스트 전 준비사항

- 접속 URL: https://www.supermujin.ai
- 브라우저: Chrome 또는 Edge 권장
- 테스트 계정: 아래 표 참고

| 역할 | 아이디 | 비밀번호 | 용도 |
|------|--------|---------|------|
| 전체관리자 | master | master1234 | 전체 관리 |
| 테스트 셀러 | seller1 | seller1234 | 셀러 흐름 테스트 |
| 테스트 관리자 | (배정 후 기재) | (배정 후 기재) | 관리자 흐름 테스트 |

## 시나리오 1: 신규 셀러 가입

**실행자:** 신규 사용자 (비로그인)

**입력 데이터:**
- 아이디: `test_flow_셀러이름` (예: `test_flow_홍길동`)
- 비밀번호: 8자리 이상
- 이름, 연락처, 이메일
- Step 2: 카테고리/지역/시간대 선택

**단계:**
1. https://www.supermujin.ai/signup 접속
2. Step 1: 기본 정보 입력 (아이디, 비밀번호, 이름, 연락처)
3. Step 2: 카테고리 선택 (식품/뷰티/생활 등), 활동 지역, 선호 시간대
4. "가입하기" 클릭

**기대 결과:**
- "가입이 완료되었습니다" 메시지 표시
- 로그인 페이지로 이동
- 계정 상태: 활성 (isActive=true)

**확인 방법:**
- 생성한 아이디로 로그인 시도 → 대시보드 접속 성공

**흔한 실수:**
- 아이디 중복 → "이미 존재하는 아이디입니다" 오류
- 비밀번호 8자리 미만 → 유효성 검사 실패

---

## 시나리오 2: 마스터가 셀러 승인

**실행자:** 전체관리자 (master)

**입력 데이터:**
- 대상: 시나리오 1에서 가입한 셀러

**단계:**
1. master 계정으로 로그인
2. "사용자 관리" 메뉴 클릭
3. 신규 가입 셀러 검색 (이름 또는 아이디)
4. "편집" 버튼 클릭
5. 정보 확인 후 필요 시 수정
6. "저장" 클릭

**기대 결과:**
- 사용자 정보 업데이트 성공
- 셀러 목록에서 확인 가능

**확인 방법:**
- 사용자 목록에서 해당 셀러가 "셀러" 권한으로 표시

---

## 시나리오 3: 센터 상품 등록 (폼 방식)

**실행자:** 전체관리자 (master)

**입력 데이터:**
- 센터: 활성 센터 중 하나 선택
- 상품명: `테스트상품_0501`
- 바코드: `TEST0501001`
- 판매가: 10,000원
- 공급가: 7,000원
- 원가: 5,000원
- 재고: 100개

**단계:**
1. master 계정으로 로그인
2. "상품 관리" 메뉴 클릭
3. "센터 상품 등록" 버튼 클릭
4. 센터 선택 드롭다운에서 센터 선택
5. 상품 코드 미리보기 확인 (C{센터번호}-{순번} 형식)
6. 상품명, 바코드, 각 가격, 재고 입력
7. "센터 상품 등록" 버튼 클릭

**기대 결과:**
- "등록되었습니다" 메시지
- 상품 목록에서 검색 가능
- 상품 코드가 자동 부여됨

**확인 방법:**
- "상품 관리" 목록에서 상품명 검색
- "센터 상품 현황"에서 해당 센터 필터 → 상품 표시

**흔한 실수:**
- 센터 미선택 → 등록 버튼 비활성
- 바코드 중복 → 오류 메시지

---

## 시나리오 3-1: 센터 상품 등록 (엑셀 업로드)

**실행자:** 전체관리자 (master)

**입력 데이터:**
- 엑셀 파일 (양식 다운로드 후 작성)

**단계:**
1. "상품 관리" 메뉴 > "엑셀 업로드" 클릭
2. 양식 다운로드 (첫 사용 시)
3. 엑셀에 상품 정보 입력 (상품명, 바코드, 가격, 재고 등)
4. 파일 선택 후 업로드
5. 미리보기 확인
6. "업로드 확정" 클릭

**기대 결과:**
- 업로드된 상품 수 표시
- 상품 목록에서 확인 가능

**흔한 실수:**
- 엑셀 양식 불일치 → 파싱 오류
- 필수 필드 누락 → 해당 행 스킵

## 시나리오 4: 셀러가 방송 등록 (센터코드 입력)

**실행자:** 셀러 (seller1)

**입력 데이터:**
- 방송명: `테스트방송_0501`
- 방송일시: 내일 날짜, 14:00
- 센터: 드롭다운에서 선택

**단계:**
1. seller1 계정으로 로그인
2. "방송" 메뉴 클릭
3. "방송 신청" 버튼 클릭
4. 방송명 입력
5. 방송일시 선택
6. 센터 선택 (드롭다운)
7. "신청" 클릭

**기대 결과:**
- "방송 신청이 완료되었습니다" 메시지
- 방송 목록에 "대기중" 상태로 표시
- 전체관리자에게 알림 발송 (Mock 모드에서는 로그만 기록)

**확인 방법:**
- 방송 목록에서 "대기중" 상태 확인
- 방송 캘린더에 표시 확인

---

## 시나리오 5: 전체관리자가 방송 승인 (또는 거절)

**실행자:** 전체관리자 (master)

### 5-A: 승인

**단계:**
1. master 계정으로 로그인
2. "방송 관리" 메뉴 클릭
3. 시나리오 4에서 등록한 방송 확인
4. "승인" 버튼 클릭

**기대 결과:**
- 상태가 "승인됨"으로 변경
- 셀러에게 승인 알림 발송

### 5-B: 거절

**단계:**
1. "거절" 버튼 클릭
2. 거절 사유 입력 (예: "일정 조정 필요")
3. "확인" 클릭

**기대 결과:**
- 상태가 "거절됨"으로 변경
- 거절 사유가 기록됨
- 셀러에게 거절 알림 발송 (사유 포함)

**확인 방법:**
- 방송 목록에서 상태 확인
- 거절 사유 표시 확인 (목록 또는 상세 페이지)

## 시나리오 6: 셀러가 거절된 경우 재신청

**실행자:** 셀러 (seller1)

**전제조건:** 시나리오 5-B에서 거절된 방송

**단계:**
1. seller1 계정으로 로그인
2. "방송" 메뉴에서 거절된 방송 확인
3. 거절 사유 확인
4. "재신청" 버튼 클릭
5. 일시 수정 (필요 시)
6. "재신청" 클릭

**기대 결과:**
- 새 방송 신청이 "대기중"으로 생성
- 재신청 횟수 제한 없음

## 시나리오 7: 셀러가 방송 시작 (재고 공유 활성화)

**실행자:** 셀러 (seller1)

**전제조건:** 시나리오 5-A에서 승인된 방송

**단계:**
1. seller1 계정으로 로그인
2. "방송" 메뉴에서 승인된 방송 클릭
3. "방송 시작" 버튼 클릭
4. 확인 다이얼로그에서 "확인" 클릭

**기대 결과:**
- 방송 상태가 "방송중"으로 변경
- 바코드 스캔 활성화
- 관리자에게 방송 시작 알림

**확인 방법:**
- 방송 목록에서 "방송중" 상태 확인
- 바코드 메뉴에서 스캔 가능 여부 확인

## 시나리오 8: 셀러가 본사/센터 상품 바코드 스캔

**실행자:** 셀러 (seller1)

**전제조건:** 시나리오 7에서 방송 시작됨

**입력 데이터:**
- 본사 상품 바코드 (ONEWMS 상품)
- 센터 상품 바코드 (시나리오 3에서 등록한 상품)

**단계:**
1. "바코드" 메뉴 클릭
2. 바코드 입력란에 바코드 번호 입력 (또는 스캔)
3. 검색 결과 확인

**기대 결과:**
- 본사 상품: 상품명, 판매가, 재고 표시 (공급가/원가 미표시)
- 센터 상품: 상품명, 판매가 표시 (공급가/원가 미표시)
- 4단계 가격 바 표시 (공급가/최소/권장/최대)
- 네이버 시세 비교 표시

**흔한 실수:**
- 방송 미시작 상태에서 센터 상품 바코드 스캔 → 차단 메시지

## 시나리오 10: 셀러가 발주서 업로드 (본사+센터 혼재)

**실행자:** 셀러 (seller1)

**입력 데이터:**
- 발주할 상품: 본사 상품 2개 + 센터 상품 1개
- 각 상품의 수량, 가격

**단계:**
1. "발주" 메뉴 클릭
2. "발주 등록" 클릭
3. 상품 선택 (본사 상품 + 센터 상품 혼합)
4. 수량, 가격 입력
5. "등록" 클릭

**기대 결과:**
- 발주 등록 성공
- 상태: "대기중" (PENDING)

## 시나리오 11: 시스템 자동 분리 결과 확인

**실행자:** 전체관리자 (master)

1. master 계정으로 로그인

**확인 방법:**
- 발주 목록에서 "(본사 책임)" / "(센터 책임)" 라벨 표시 확인

## 시나리오 12: 가상계좌 발급 → 알림 발송 → 입금 확인 → 출고

**실행자:** 전체관리자 (master)

**전제조건:** 시나리오 10의 발주

> 현재 Mock 모드: 가짜 계좌번호가 발급됩니다.
> Toss Payments 키 발급 후 실제 계좌가 발급됩니다.

**단계:**
1. 발주 상세 페이지에서 "가상계좌 발급" 클릭
2. 은행, 금액 확인
3. "발급" 클릭
4. Mock 모드: 가짜 계좌번호 표시 확인

**기대 결과 (Mock 모드):**
- 가상계좌 정보 표시 (은행: 테스트은행, 계좌번호: MOCK-xxxxx)
- 셀러에게 알림 발송 (Mock: 로그만 기록)

**기대 결과 (운영 모드 - Toss 키 발급 후):**
- 실제 가상계좌 발급 (국민/신한/우리 등)
- 셀러에게 카카오 알림톡 발송
- 입금 시 웹훅으로 자동 확인
- 입금 확인 후 상태 → PAID
- 출고 처리 가능

## 시나리오 13: 세금계산서 발행 (Mock 모드)

4. "발행" 클릭

**기대 결과 (Mock 모드):**
- "세금계산서 발행 완료 (Mock)" 메시지

**기대 결과 (운영 모드 - PopBill 키 발급 후):**
- PopBill을 통해 실제 세금계산서 발행
- 국세청 전송
- 발행 상태 추적 가능
